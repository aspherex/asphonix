# GPUI 0.2.2 gaps and how ASPHONIX works around them (no fork)

| Gap | Workaround here | Residual |
|---|---|---|
| No letter-spacing in `TextStyle` | `tracking.rs`: lay out the line once with the text system, paint each glyph with the public `Window::paint_glyph` at `x + i*tracking` (spacing after every glyph); width = shaped + n*tracking (unit-tested) | Used for caps labels, headlines, title block. Body/mono-data rows use native text (0.01-0.02em is < 1 px) so ellipsis keeps working; tracked labels cannot truncate; per-glyph painting skips emoji |
| No text-transform | caps applied in the same helper (`spec.caps`) and in buttons | none |
| No radial gradients | `examples/gen_backdrop.rs` renders dark "oil slick" and light "pearl" to 480x270 dithered PNGs, drawn once behind the body/dock, dropped on minimize | stretched 4x (soft washes, no visible loss) |
| No minimize callback; swallowed `WM_SIZE` | `winffi::size_hook`: `SetWindowSubclass` on the HWND obtained via `HasWindowHandle for Window` | Windows only; macOS hook TBD |
| Permanent vsync thread (`DwmFlush` loop) | none possible without a patch | ~0-3 % of one core idle; ~0 when minimized in 2 of 3 runs, not guaranteed. A `set_vsync_suspended` hook would need upstream |
| Quits when the last window closes; cannot release D3D device | n/a | ~22 MB WS / ~150 MB commit / ~54 MB VRAM floor per process |
| No scrollbar for `uniform_list` | `widgets/scrollbar.rs` reading `UniformListScrollHandle` (public) and setting `base_handle.set_offset` while dragging | no track click paging |
| Svg ignores the parent's `text_color` | explicit colour per icon; hover tints through `group_hover("hv")` (`icon_g`) | each icon call carries its colours |
| `text_ellipsis` in a column flex container collapsed to "…" | **Solved** by `text.rs` (`Txt`): a custom element with a *measured* layout node (width = min(natural, available), shrinkable only with `.ellipsis()`) that paints the longest glyph prefix + "…" itself. The earlier guess (missing "…" glyph) was wrong: the cause was `text_ellipsis` being applied to a node whose width the text measure did not know. `typo::ellipsis_line` was deleted | none |
| Text input | own widget (`text_input.rs`, derived from GPUI's example): caret, selection, word navigation, double/triple click, clipboard | undo/redo (Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z, typing runs coalesced) added; right-click edit menu (Undo, Redo, Cut, Copy, Paste, Select all; off inside modals, where the shell menu would paint below the dialog); IME composition wired (`EntityInputHandler`) but **not exercised with a real IME**; no bidi |
| Accessibility | none | GPUI 0.2.2 has no accesskit/UIA: screen readers see an unlabeled window. Blocker for a real release |
| Text antialiasing is fixed | GPUI's DirectWrite path always rasterises in `DWRITE_TEXT_ANTIALIAS_MODE_GRAYSCALE` (no ClearType); gamma/contrast come from the system DirectWrite rendering parameters, and there is no public API on `Window`/`TextSystem`/`Application` to change them (the `ZED_FONTS_*` env vars exist only in the Linux renderer) | grayscale AA only |
| Rust edition 2024, `impl Trait` capture rules (`+ use<>`) | followed | friction only |
| Auto margin next to `flex-grow` siblings in a row with `gap` | Taffy reserves the gaps in the free space the auto margin takes but positions the items without them (top bar: items 48 px short of the right edge, no gap after the nav). Use an explicit `div().flex_1()` spacer instead of `ml_auto()`; an item that should fill first gets a 1000:1 `flex-grow` | none |
| Intrinsic width of shrinkable measured leaves | A shrinkable (`min_w_0`) measured node inside a non-shrinking auto-width container makes taffy over-count the container by ~10 px (the connection pill). `Txt` therefore shrinks only when asked (`.ellipsis()`) | none |
| Layout is in whole device pixels | Taffy rounds every node to device px (1.5 per logical px at 150 %) | edges can land one device pixel off a fractional design value |
| Borders are floored to whole device px | 1 px borders are drawn as 1 device px at every scale | thin borders at 150 % |
| Focusable ancestors take the focus back on mouse down | A `track_focus` ancestor (shell root, list body) refocuses itself in the bubble phase of the same mouse-down; text inputs and the context menu call `cx.stop_propagation()` after taking focus | none |
| Font weights 500/600 resolved to 400/700; no kerning | **Our files, fixed.** `scripts/fix-font-families.mjs`: the bundled static instances name the 500/600 faces "<Family> Medium/SemiBold" (nameID 1), which DirectWrite files under separate families, and the SemiBold face's `STAT` table made it resolve 600 to Bold; the script sets nameID 1/2 to one family and drops 16/17/21/22 and `STAT`. DirectWrite via GPUI also leaves `kern` off ("AV", "PLAY" 2-6 % wider): `text::css_font` requests it for every face | none |
| Wheel scrolling jumps (GPUI) | `widgets/smooth.rs`: one capture-phase wheel listener + per-container overlay hitboxes; an inverse-delta ease-in-out curve (100-200 ms, velocity-keeping retarget), 100 px per notch, touchpad (pixel) deltas unanimated | none |
| Caption mouse presses are swallowed (Windows) | GPUI turns `WM_NCLBUTTONDOWN` into a `MouseDown` and returns 0 when it was handled; any focusable ancestor (`track_focus`) `prevent_default`s every mouse down, so the press never reaches `DefWindowProcW` (no move loop) and GPUI never arms its min/max/close handling; there is no Windows `start_window_move`. The main-window subclass (`winffi::size_hook`) hands caption presses/double-clicks/right-clicks to `DefWindowProcW` and runs the caption buttons as `WM_SYSCOMMAND` on press + release. The buttons `.occlude()` the title bar Drag hitbox (painted first, it otherwise wins the window-control hit test) | Windows only |
| `Window::request_animation_frame` outside render/paint panics | it unwraps the current view, which only exists while a view renders/paints; from an event listener it aborts the app. Listeners `cx.notify()` and the render requests frames | none |
| Right-to-left text and layout | not supported, not verified: GPUI 0.2.2 shapes and lays out left-to-right (`Txt` paints glyphs left to right, flex rows never mirror). The shipped locales (`en`, `de`) are LTR; an RTL locale needs bidi in `text.rs` and mirrored layouts first | RTL locales out of scope for 0.x |
| `TestWindow` has no raw window handle (`#[gpui::test]`) | `HasWindowHandle for TestWindow` is `unimplemented!()`, so `winffi::hwnd_of` returns `None` in test builds and `Shell::new` (HWND, minimize hook) mounts in a test window | the native minimize hook is not exercised by tests; they call `Shell::on_minimize_change` directly |
| `gpui::Timer` is smol's wall-clock timer | `advance_clock` in tests only drives `BackgroundExecutor::timer`; code that waits on `gpui::Timer::after` (tracks filter debounce, the 300 ms `EmptyWorkingSet` after suspend, perf-script hooks) is not driven by the test clock, so tests do not assert on it | switching those waits to `cx.background_executor().timer(..)` would make them testable |
