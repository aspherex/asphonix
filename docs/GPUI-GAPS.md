# GPUI 0.2.2 gaps and how this repo works around them (no fork)

| Gap | Workaround here | Residual |
|---|---|---|
| No letter-spacing in `TextStyle` | `tracking.rs`: lay out the line once with the text system, paint each glyph with the public `Window::paint_glyph` at `x + i*tracking` (CSS semantics: spacing after every glyph); width = shaped + n*tracking (unit-tested) | Used for caps labels, headlines, title block. Body/mono-data rows use native text (0.01-0.02em is < 1 px) so ellipsis keeps working; tracked labels cannot truncate; per-glyph painting skips emoji |
| No text-transform | caps applied in the same helper (`spec.caps`) and in buttons | none |
| No radial gradients (`--bg-canvas`) | `examples/gen_backdrop.rs` renders dark "oil slick" and light "pearl" to 480x270 dithered PNGs, drawn once behind the body/dock, dropped on minimize | stretched 4x (soft washes, no visible loss expected; not pixel-diffed) |
| No minimize callback; swallowed `WM_SIZE` | `winffi::size_hook`: `SetWindowSubclass` on the HWND obtained via `HasWindowHandle for Window` | Windows only; macOS hook TBD |
| Permanent vsync thread (`DwmFlush` loop) | none possible without a patch | ~0-3 % of one core idle; ~0 when minimized in 2 of 3 runs, not guaranteed. A `set_vsync_suspended` hook would need upstream |
| Quits when the last window closes; cannot release D3D device | n/a | ~22 MB WS / ~150 MB commit / ~54 MB VRAM floor per process |
| No scrollbar for `uniform_list` | `widgets/scrollbar.rs` reading `UniformListScrollHandle` (public) and setting `base_handle.set_offset` while dragging | no track click paging |
| Svg ignores the parent's `text_color` | explicit colour per icon; hover tints through `group_hover("hv")` (`icon_g`) | each icon call carries its colours |
| `text_ellipsis` in a column flex container collapsed to "…" | **Solved** by `text.rs` (`Txt`): a custom element with a *measured* layout node (width = min(natural, available), shrinkable only with `.ellipsis()`) that paints the longest glyph prefix + "…" itself. The earlier guess (missing "…" glyph) was wrong: the cause was `text_ellipsis` being applied to a node whose width the text measure did not know. `typo::ellipsis_line` was deleted | none |
| Text input | own widget (`text_input.rs`, derived from GPUI's example): caret, selection, word navigation, double/triple click, clipboard | no undo/redo, no context menu; IME composition wired (`EntityInputHandler`) but **not exercised with a real IME**; no bidi |
| Accessibility | none | GPUI 0.2.2 has no accesskit/UIA: screen readers see an unlabeled window. Blocker for a real release |
| Text weight/softness vs Chromium | **Measured** (docs/PARITY.md "Text fidelity"). GPUI's DirectWrite path always rasterises in `DWRITE_TEXT_ANTIALIAS_MODE_GRAYSCALE` (`platform/windows/direct_write.rs`), Chromium on Windows uses ClearType (LCD subpixel) AA, so glyph edges carry colour fringes on the web side and are grey on the native side. Gamma/contrast come from the system DirectWrite rendering parameters (`directx_renderer.rs: get_gamma_ratios`, `GetGrayscaleEnhancedContrast`) and there is no public API on `Window`/`TextSystem`/`Application` to change them (the `ZED_FONTS_GAMMA`/`ZED_FONTS_GRAYSCALE_ENHANCED_CONTRAST` env vars exist only in the blade/Linux renderer). What can be adjusted from our side: the fonts (now converted from the same @fontsource files as the web's woff2 by `scripts/gen-fonts.mjs`; the spike's TTFs had different Space Grotesk advances) and nothing else | grayscale vs LCD AA is a fixed difference |
| Rust edition 2024, `impl Trait` capture rules (`+ use<>`) | followed | friction only |
| `margin-left: auto` next to `flex-grow` siblings in a row with `gap` | Taffy reserves the gaps in the free space the auto margin takes but positions the items without them (top bar: items 48 px short of the right edge, no gap after the nav). Use an explicit `div().flex_1()` spacer instead of `ml_auto()`; where the web item also has `flex: 1; max-width` give it a 1000:1 `flex-grow` so it fills first | none |
| Intrinsic width of shrinkable measured leaves | A `flex-shrink: 1`, `min-width: 0` measured node inside a `flex-shrink: 0` auto-width container makes taffy over-count the container by ~10 px (the connection pill). `Txt` therefore shrinks only when asked (`.ellipsis()`) | none |
| Layout is in whole device pixels | Taffy rounds every node to device px (1.5 per CSS px at 150 %), Chromium lays out in 1/64 px. Edges can differ by one device pixel (0.667 CSS px); the parity runner counts a box as deviating above 1 CSS px and reports the literal > 0.5 px count too | up to 1 device px per edge |
| 1 CSS px borders | Chromium paints a 1.5 device px border with edges snapped to the pixel grid (1 or 2 px depending on position); GPUI floors borders to 1 device px | border pixels differ in the non-text pixel diff (the largest remaining non-text contributor) |
| `Window::dispatch_event` is public but returns a crate-private type | Calling it from outside GPUI is a compile error (type privacy). The parity hook delivers mouse input as Win32 messages (`SendMessageW` + `SetKeyboardState` for Ctrl/Shift/Alt) *outside* any app update and keys through `Window::dispatch_keystroke` on the async window context, never inside an update of the `Shell` entity (actions bound on the root update it and would re-enter its lease) | parity feature only |
| Focusable ancestors take the focus back on mouse down | A `track_focus` ancestor (shell root, list body) refocuses itself in the bubble phase of the same mouse-down; text inputs and the context menu call `cx.stop_propagation()` after taking focus | none |
